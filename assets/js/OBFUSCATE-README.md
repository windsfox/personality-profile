# 计分规则"轻量混淆"说明（浏览器版）

## 这个功能解决什么
让发布版本里 `scoring.js`（计分算法）、`interpretations.js`（判罚阈值与解读）变成**压缩后的单行代码**——去掉了所有注释、空行、格式化，普通用户、脚本、甚至 AI 一眼读不出"分数怎么算出来的"。

## 必须坦白的边界
这是**压缩混淆**，不是加密。前端代码天然可被开发者工具查看，专业逆向人员仍能慢慢读懂。它提高的是"阅读门槛"，不是"绝对保密"。
- 想要真正不可见 → 需要把计分逻辑搬到后端服务器（涉及域名/备案/HTTPS，工程较大）。
- 对绝大多数"不想让人轻易看懂"的诉求，压缩混淆已经够用。

## 当前敏感文件清单
见 `obfuscate.js` 中的 `Obfuscate.minify()` 可处理任意代码字符串。建议对 `scoring.js`、`interpretations.js` 两个文件做混淆。

## 日常开发：不受影响
- 你平时改的是 **`scoring.js` / `interpretations.js` 这些清晰源码**，格式、注释照常，方便排错。
- 页面一直引用清晰版，所以**开发时永远可读可改**。

## 发布步骤
1. 在浏览器控制台中，获取清晰源码的文本（例如直接打开文件复制内容）。
2. 调用混淆工具：
   ```js
   var compressed = Obfuscate.minify(sourceCode);
   console.log(compressed);
   ```
3. 把压缩后的单行代码覆盖回 `scoring.js` / `interpretations.js` 同名文件。
4. 保存后即为发布的"防读取"版本，页面正常加载。

## 未来修改计分规则的完整姿势
1. 改 `scoring.js`（清晰版）；
2. （发布时）用 `Obfuscate.minify()` 生成压缩版，覆盖 `scoring.js` 对应文件。

清晰源码永不丢失，`assets/js/` 始终是权威可维护版本。
